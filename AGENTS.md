# AGENTS.md — QGIS-плагин для данных NISAR (фокус: растительность)

Этот файл — рабочее задание и правила для агента-разработчика. Читай целиком перед началом работы. Пункты, помеченные **[ПРОВЕРИТЬ]**, не подтверждены — проверь по первоисточнику до того, как опираться на них.

---

## 1. Цель

Сделать собственный плагин QGIS для работы с данными миссии NISAR (NASA–ISRO SAR):

1. найти сцены (по экстенту карты / слою-AOI / датам / продукту);
2. скачать или открыть их (локально или стримингом из облака);
3. корректно загрузить в QGIS с правильной геопривязкой;
4. посчитать готовые продукты для мониторинга растительности;
5. выгрузить результат в GeoTIFF/COG.

Ключевое требование: **несколько взаимозаменяемых вариантов реализации** (backend'ов) для чтения, доступа и обработки, с автоопределением лучшего доступного варианта и возможностью выбрать вручную.

Целевая аудитория — пользователь GIS, не программист. Всё должно работать через GUI и через Processing Toolbox (чтобы можно было использовать в моделях и скриптах).

## 2. Проверенные факты о данных

### 2.1 Где брать данные
- **L-диапазон** (JPL/NASA): архив **ASF DAAC**, бесплатно, нужен аккаунт **Earthdata Login (EDL)**.
- Поиск: ASF **Vertex**, **Earthdata Search**, Python: `asf_search`, `earthaccess`, ASF SearchAPI (REST).
- Данные лежат в **AWS S3 (Earthdata Cloud)** — возможен прямой S3-доступ и стриминг без полного скачивания.
- **S-диапазон** (ISRO): платформа **Bhoonidhi**, бета-продукты. В v1 плагина не поддерживать (только заглушка/ссылка), но архитектуру не закрывать для S-диапазона (в идентификаторах продуктов встречается `SSAR`; у L-диапазона `LSAR`).

### 2.2 Статусы данных (критично для качества)
- **BETA** — ранние продукты (в т.ч. релиз февраля 2026 за 17.10.2025–20.01.2026): не полностью откалиброваны, есть известные проблемы.
- **PROVISIONAL** — публичный релиз с 20.07.2026, съёмки начиная с 17.06.2026: откалиброваны полностью, валидированы частично.
- Более ранние наблюдения первого года дозагружаются, полный научный архив ожидается к концу 2026.
- **Плагин обязан показывать статус продукта (BETA/PROVISIONAL) в результатах поиска и предупреждать при смешивании BETA и PROVISIONAL в одном временном ряду.** **[ПРОВЕРИТЬ]** как статус закодирован в метаданных/имени файла (не угадывать — найти в NISAR Data User Guide: nisar-docs.asf.alaska.edu).

### 2.3 Формат и чтение
- Продукты — **HDF5**, но структурно ведут себя как netCDF.
- GDAL получил нативный драйвер NISAR в **3.13**; QGIS использует его начиная с **4.2**.
- В старых версиях: `.h5` открывается без правильной геопривязки (растр «у берегов Африки») и QGIS может падать. Обходной путь: открывать файл как `.nc` (**не переименовывать оригинал — делать симлинк/копию или использовать VSI-путь `NETCDF:"path.h5":/subdataset`**). **[ПРОВЕРИТЬ]** работает ли префикс `NETCDF:` с `.h5` напрямую на целевых версиях GDAL.
- Падения QGIS иногда лечатся удалением `.aux.xml`, созданного рядом с файлом. Плагин должен по возможности **не создавать** `.aux.xml` рядом с исходником (использовать `GDAL_PAM_ENABLED=NO` при чтении или отдельный PAM-каталог `GDAL_PAM_PROXY_DIR`).
- **GSLC/RSLC — комплексные данные**, QGIS их не показывает. Амплитуда извлекается через derived-subdataset драйвер, например:
  `gdal_translate -of GTiff DERIVED_SUBDATASET:AMPLITUDE:NETCDF:/path/nisar.nc:/science/LSAR/GSLC/grids/frequencyA/HH amplitude.tif`
- Типичный путь слоёв GCOV: `/science/LSAR/GCOV/grids/frequencyA/<HHHH|HVHV|...>` (+ маска, число looks). **[ПРОВЕРИТЬ]** точные имена групп и слоёв на реальном файле, а также единицы (линейная мощность, гамма-0 и т. п.) — по атрибутам файла, не по памяти.
- Имя файла GCOV выглядит как `NISAR_L2_PR_GCOV_...h5`. Размеры: от <1 ГБ до ~7 ГБ на файл.

### 2.4 Уже существующие проекты (изучить, не копировать вслепую)
- `opengeos/qgis-nasa-earthdata-plugin` — общий поиск/визуализация Earthdata в QGIS.
- `dk0885807-dotcom/NISAR-GCOV-Processor` — QGIS-плагин для GCOV (инспекция, экспорт в GeoTIFF Float32, RGB, спекл-фильтр).
- `JPL-Devin/nisar-hdf5-gdalplugin` и conda-пакет `nisar-forge::gdal-driver-nisar` — сторонний GDAL-драйвер с S3-стримингом (**[ПРОВЕРИТЬ]** зрелость и лицензию; пакет на момент проверки собран под linux-64).
- `dharmendraisro/nisar-polarimetric-training` — учебные ноутбуки по поляриметрии GCOV (полезны как справочник алгоритмов).

Перед началом: проверь лицензии. Код чужих плагинов не переносить без совместимой лицензии; идеи и алгоритмы — можно, с указанием источника.

## 3. Принципы

1. **Не модифицировать исходные файлы.** Только чтение.
2. **Не угадывать CRS.** Если геопривязка в метаданных отсутствует или невалидна — сообщить пользователю, не назначать проекцию молча.
3. **Научные значения сохранять.** Экспорт для анализа — Float32 в исходных единицах. Растяжка/дБ-преобразование — только для отображения, отдельным слоем/стилем.
4. **Тяжёлое — в фоне.** Поиск, скачивание, обработка — через `QgsTask`, с прогрессом и отменой. GUI не должен зависать.
5. **Большие файлы — оконно/тайлами**, без загрузки всего массива в память. Целевая машина: 16 ГБ RAM.
6. **Секреты.** EDL-токен/пароль хранить только в `QgsAuthManager` (или через `earthaccess`/`~/.netrc`, которые настраивает пользователь). Никогда не писать в проект, логи, настройки в открытом виде.
7. **Совместимость.** QGIS 3.28 LTR+ и 4.x. Импорты только через `qgis.PyQt` (Qt5/Qt6). Не использовать API, удалённые в QGIS 4.
8. **Честность интерфейса.** Если функция недоступна на текущей версии GDAL/QGIS — показать понятное сообщение и предложить обходной путь, а не падать.

## 4. Варианты реализации (обязательная часть)

Плагин строится вокруг абстракций. Для каждой оси — минимум два варианта, выбор в настройках («Авто» по умолчанию).

### 4.1 Ось А — Чтение HDF5 (Reader backend)

| Вариант | Как работает | Плюсы | Минусы | Когда авто-выбор |
|---|---|---|---|---|
| **A1. Native GDAL** | GDAL ≥ 3.13 (QGIS ≥ 4.2), открытие как обычный растр | Ноль зависимостей, правильная геопривязка | Требует новых версий | GDAL ≥ 3.13 |
| **A2. GDAL + netCDF-обход** | `NETCDF:` / симлинк `.nc` для старых GDAL | Работает на LTR | Хрупко, возможны падения, `.aux.xml` | GDAL < 3.13 |
| **A3. h5py/rasterio/xarray** | Чтение массивов и геопривязки вручную из HDF5 (coords + CRS из метаданных), запись во временный GeoTIFF/VRT | Полный контроль, оконное чтение | Нужны pip-зависимости, больше кода | Если A1/A2 не дали валидный CRS |
| **A4. Сторонний GDAL-драйвер** (`gdal-driver-nisar`) | Опциональный внешний драйвер | S3-стриминг, block-оптимизация | Внешняя зависимость, платформенные ограничения | Только если найден и включён пользователем |

Требования: единый интерфейс `Reader.open(path) -> ProductHandle`, `ProductHandle.list_layers()`, `.read_window(layer, window)`, `.georef()`, `.metadata()`. Авто-выбор с проверкой на маленьком тестовом чтении и понятным логом «использован backend X, потому что Y».

### 4.2 Ось Б — Доступ к данным (Access backend)

| Вариант | Описание |
|---|---|
| **Б1. Локальные файлы** | Пользователь указывает папку/файл. Базовый вариант, всегда доступен. |
| **Б2. Поиск + скачивание (asf_search)** | Поиск по AOI/датам/типу продукта, footprints на карте, скачивание с EDL-авторизацией, докачка, проверка размера. |
| **Б3. earthaccess** | Альтернатива Б2 через `earthaccess` (логин, поиск CMR, скачивание/fsspec). |
| **Б4. Облачный стриминг (S3/HTTPS + range requests)** | Чтение нужного окна без скачивания всего файла (через `/vsicurl/`, `/vsis3/` или fsspec). Помечать как экспериментальный, пока не подтверждено на реальных данных. |
| **Б5. Внешний плагин** | Если установлен `qgis-nasa-earthdata-plugin` — принять его результаты как вход (не дублировать функционал, дать кнопку «Открыть в NISAR-плагине»). |

Все варианты возвращают единую структуру `SceneRecord` (id, product_type, level, instrument, statuses[BETA/PROVISIONAL], acquisition_time, footprint, size, urls, polarizations, mode).

### 4.3 Ось В — Обработка (Processing backend)

| Вариант | Описание |
|---|---|
| **В1. Processing-алгоритмы на `gdal:`/`native:` (растровый калькулятор)** | Простые индексы, без внешних зависимостей. |
| **В2. NumPy оконно (по блокам)** | Основной вариант для индексов, фильтров, дБ; память под контролем. |
| **В3. Поляриметрия (только full-pol GCOV)** | Разложения (Pauli, Freeman–Durden и др.), H/A/alpha. Тайловая обработка, отдельный модуль, опциональные зависимости. |
| **В4. Экспорт-только** | Выгрузить слои в GeoTIFF/COG без вычислений (для тех, кто считает во внешнем софте). |

### 4.4 Ось Г — Способ работы пользователя
- **Г1. Диалог-плагин** с вкладками: Поиск → Загрузка → Обработка → Экспорт.
- **Г2. Processing Provider** — те же операции как алгоритмы (`NISAR: Search`, `NISAR: Open GCOV layers`, `NISAR: Vegetation indices`, …). Обязательно, так как это даёт модели и пакетный запуск.
- **Г3. (Опционально, потом)** headless-CLI с тем же ядром для использования вне QGIS и агентами.

Ядро (без импортов QGIS GUI) вынести в отдельный пакет `nisar_core`, чтобы его можно было тестировать без QGIS и переиспользовать в Г3.

## 5. Функциональные модули

1. **Поиск сцен.** AOI: экстент карты / выделенный объект / активный векторный слой. Фильтры: даты, уровень (L1/L2/L3), тип (GCOV, GSLC, …), поляризация, статус данных. Footprints на карте, таблица результатов с размером и статусом.
2. **Загрузка.** Очередь, прогресс, отмена, докачка, каталог кэша, оценка занимаемого места до старта.
3. **Инспектор продукта.** Дерево групп/слоёв HDF5, ключевые метаданные (время, орбита, режим, поляризации, CRS, размер пикселя, статус калибровки), предупреждения (BETA, отсутствие CRS).
4. **Загрузка слоёв в проект.** Выбор конкретных слоёв (не «всё по умолчанию»), автоматические имена, группы в дереве слоёв, сохранённое обрезание по AOI.
5. **Стили по умолчанию.** Перцентильная растяжка 2–98%, отображение в дБ, RGB-пресеты; всё как стиль/виртуальный слой, без изменения данных.
6. **Маскирование и качество.** Использовать слои маски продукта; опция «применить маску».
7. **Экспорт.** GeoTIFF (Float32), COG, опция обрезки по AOI и перепроекции.
8. **Галерея пресетов.** Все пресеты из п. 6 в одном месте: карточка с названием и подсказкой «для чего это», панель «Что это?» (назначение, когда применять, как читать, формула, ограничения), индикатор доступности для выбранного файла. Тексты берутся из реестра `presets.py`, не дублируются.

## 6. Пресеты для растительности

Все пресеты встроены в плагин: каждый — отдельный Processing-алгоритм **и** карточка в «Галерее пресетов» (вкладка диалога). **Перед реализацией проверить единицы входных слоёв** (линейная мощность vs дБ) и применять формулы только к линейным значениям.

### 6.0 Реестр пресетов и встроенные пояснения

Пресеты описываются в одном месте — `nisar_core/presets.py` (реестр), а GUI, Processing-алгоритмы и документация строятся из него. Дублировать тексты вручную нельзя.

Поля записи реестра:

| Поле | Назначение |
|---|---|
| `id` | Стабильный идентификатор (`hv_db`, `rvi`, …) |
| `name` | Название в интерфейсе (i18n) |
| `hint` | Подсказка в одну строку (tooltip, ≤ 100 символов): «для чего это» |
| `purpose` | 1–2 предложения: какую задачу решает |
| `when_to_use` | Когда применять / когда нет |
| `how_to_read` | Как интерпретировать значения (что значит «больше/меньше») |
| `requires` | Нужные слои и поляризации (например, `HHHH`, `HVHV`; `full_pol=True`) |
| `formula` | Формула (текстом) и ссылка на источник **[ПРОВЕРИТЬ]** |
| `caveats` | Ограничения и типичные ошибки интерпретации |
| `output` | Тип результата, единицы, стиль по умолчанию (QML) |

Где пояснения должны отображаться:
1. **Галерея пресетов** — карточки с названием, `hint`, значком доступности (серый + причина, если не хватает поляризаций или слоёв в выбранном файле).
2. **Панель «Что это?»** справа от параметров пресета: `purpose`, `when_to_use`, `how_to_read`, `formula`, `caveats`.
3. **Processing:** `shortHelpString()` алгоритма собирается из тех же полей.
4. **Легенда результата:** после выполнения слою присваивается стиль, а в свойствах слоя (метаданные) записывается краткое пояснение «как читать» и применённая формула.
5. **Автодоступность:** пресеты, для которых в файле нет нужных поляризаций, не скрываются, а показываются неактивными с объяснением почему.

Тексты пояснений на русском и английском лежат в `i18n/` и должны быть краткими (по 1–3 предложения на поле). Стартовые тексты приведены в п. 6.2.

### 6.1 Список пресетов и порядок реализации

Пресеты 1–6 — v1 (M3–M4), пресеты поляриметрии (Pauli, Freeman–Durden, H/A/alpha из п. 7 ниже) — M5. Идентификаторы и тексты — в п. 6.2.

1. **Кросс-поляризация HV.** Слой HVHV в линейном виде и в дБ (`10*log10(x)`, с защитой от нулей/NaN). Основной индикатор объёма растительности/биомассы.
2. **Cross-ratio.** `HV/HH` (в дБ: `HV_dB − HH_dB`).
3. **RVI (Radar Vegetation Index).**
   - dual-pol (HH/HV): `4·HV / (HH + HV)`
   - full-pol: `8·HV / (HH + VV + 2·HV)`
   Учитывать, что для разных наборов поляризаций формулы разные; выбирать автоматически по составу слоёв в файле, показывая пользователю, какая формула применена. **[ПРОВЕРИТЬ]** формулы по литературе и задокументировать источник в справке алгоритма.
4. **Временной ряд по AOI.** Извлечение статистики (среднее/медиана/стд.) слоя по полигонам через даты, вывод в таблицу CSV и график (matplotlib или Qt Charts). Предупреждение при смешении BETA/PROVISIONAL и разных режимов/геометрий (орбита, восходящая/нисходящая).
5. **Детектор изменений.** Разность в дБ между двумя датами с порогом → бинарная маска (вырубка/нарушение).
6. **Спекл-фильтр (опционально).** Медиана/бокс 3×3, 5×5, 7×7 — только для визуализации или как явно отдельный выходной слой; не подменять научные данные.
7. **Поляриметрия (модуль В3, позже).** Pauli RGB, Freeman–Durden, H/A/alpha для full-pol, тайловая обработка.

### 6.2 Стартовые тексты пояснений (RU; агент делает EN-версию и уточняет по литературе)

Это черновые формулировки. Всё, что содержит числа-пороги или утверждения о физике, агент сверяет с литературой и документацией NISAR до релиза; спорные утверждения смягчает или убирает.

**1. HV (кросс-поляризация), дБ** — `hv_db`
- *hint:* Общий «объём» растительности: чем выше, тем больше рассеивающей биомассы.
- *purpose:* Показывает обратное рассеяние в кросс-поляризации. Оно возникает главным образом при многократном рассеянии в кронах, ветвях и стеблях, поэтому хорошо отражает структуру и объём растительности.
- *when_to_use:* Карты леса и не-леса, сравнение густоты растительности, основа для временных рядов. Хуже подходит для оценки очень высокой биомассы: сигнал со временем перестаёт расти (насыщение).
- *how_to_read:* Выше (менее отрицательные дБ) — больше растительного объёма. Голая почва и вода дают низкие значения.
- *caveats:* Зависит от влажности растительности и почвы, от режима съёмки и угла. Значения из разных орбит и геометрий напрямую не сравнивать.

**2. Cross-ratio (HV/HH)** — `cross_ratio`
- *hint:* Отношение «объёмного» рассеяния к «поверхностному» — помогает отделить растительность от почвы.
- *purpose:* Нормирует HV на HH, частично уменьшая влияние общей яркости сцены и угла падения.
- *when_to_use:* Разделение открытых и покрытых растительностью участков, слежение за ростом культур.
- *how_to_read:* В дБ — разность `HV_dB − HH_dB`. Больше — выше доля объёмного рассеяния.
- *caveats:* Чувствителен к шуму на слабых сигналах (голая почва, вода). Требует HH и HV одновременно.

**3. RVI — радарный вегетационный индекс** — `rvi`
- *hint:* Радарный аналог «индекса зелени»: 0 — почти нет растительности, выше — больше.
- *purpose:* Единый безразмерный индекс густоты растительности, менее зависимый от яркости сцены, чем сырое обратное рассеяние.
- *when_to_use:* Сезонная динамика культур, сравнение участков, ситуации с облачностью, где оптические индексы недоступны.
- *how_to_read:* Обычно принимает значения от 0 до порядка 1; больше — гуще растительный покров. Точный диапазон зависит от формулы и набора поляризаций.
- *formula:* dual-pol и full-pol используют разные формулы (см. п. 6 выше); плагин показывает, какая применена.
- *caveats:* Не эквивалентен NDVI и не «измеряет зелень» — реагирует на структуру и влажность. Формулу и диапазоны подтвердить по источнику **[ПРОВЕРИТЬ]**.

**4. Временной ряд по AOI** — `timeseries`
- *hint:* Как менялся сигнал на вашем участке по датам: сезон, уборка, вырубка.
- *purpose:* Считает статистику выбранного слоя или индекса (среднее, медиана, стандартное отклонение) по полигонам на всех датах и строит график и таблицу.
- *when_to_use:* Фенология культур, поиск даты уборки или посева, слежение за состоянием леса.
- *how_to_read:* Сглаженные сезонные изменения — норма; резкий скачок вниз или вверх — событие (уборка, нарушение, изменение влажности).
- *caveats:* Не смешивать BETA и PROVISIONAL; сравнивать сцены одной орбиты и геометрии. Дожди и заморозки могут вызвать скачки, не связанные с растительностью.

**5. Детектор изменений** — `change_db`
- *hint:* Показывает, где сигнал заметно изменился между двумя датами (например, вырубка).
- *purpose:* Разность двух сцен в дБ и бинарная маска по порогу.
- *when_to_use:* Быстрый поиск нарушений леса, уборки, затопления после события.
- *how_to_read:* Сильное падение HV часто указывает на потерю растительной структуры; рост — на рост или увлажнение. Направление интерпретируйте вместе с контекстом.
- *caveats:* Порог задаёт пользователь; стартовое значение подбирайте на своих данных (плагин предлагает умолчание, но не считает его универсальным). Сцены должны быть из одной геометрии; влажность даёт ложные срабатывания.

**6. Спекл-фильтр** — `speckle`
- *hint:* Сглаживает «зернистость» радарного изображения для лучшего вида.
- *purpose:* Снижает спекл-шум (медиана или бокс 3×3, 5×5, 7×7).
- *when_to_use:* Визуализация и карты для отчётов. Для количественного анализа сначала подумайте, нужен ли он: фильтр размывает детали.
- *how_to_read:* Значения остаются в тех же единицах, но теряют мелкие детали.
- *caveats:* Всегда сохраняется как **отдельный** слой; исходные научные значения не перезаписываются.

**7. Поляриметрический RGB (Pauli)** — `pauli_rgb` *(full-pol, позже)*
- *hint:* Цветная картинка, где цвет подсказывает механизм рассеяния.
- *purpose:* Комбинирует поляризационные каналы в RGB для быстрого визуального разделения типов поверхности.
- *when_to_use:* Обзорный осмотр сцены: поверхность, «двойное отражение» (строения, стволы у воды), объёмное рассеяние (кроны).
- *how_to_read:* Соответствие цветов механизмам зависит от выбранной схемы — легенда рядом с картой обязательна **[ПРОВЕРИТЬ]**.
- *caveats:* Нужен full-pol режим; это визуализация, а не количественный продукт.

**8. Разложение Фримана–Дюрдена** — `freeman_durden` *(full-pol, позже)*
- *hint:* Разбивает сигнал на вклад поверхности, двойного отражения и растительности.
- *purpose:* Оценивает долю мощности по трём механизмам рассеяния.
- *when_to_use:* Разделение лес / поле / вода / застройка, изучение структуры покрова.
- *how_to_read:* Три слоя мощности; преобладание объёмной составляющей типично для густой растительности.
- *caveats:* Нужен full-pol; известны артефакты (например, отрицательные мощности, которые надо обрабатывать явно). Обрабатывать тайлами.

**9. H/A/alpha (Клауд–Поттье)** — `h_a_alpha` *(full-pol, позже)*
- *hint:* Классификация «по типу рассеяния» без обучающей выборки.
- *purpose:* Считает энтропию (H), анизотропию (A) и угол α, описывающие степень «хаотичности» и характер рассеяния.
- *when_to_use:* Исследование структуры покрова, вход для классификации.
- *how_to_read:* Высокая энтропия — смесь механизмов (типично для лесов); низкая — доминирует один механизм (например, гладкая поверхность).
- *caveats:* Только full-pol; нужна осторожность с интерпретацией без опыта в поляриметрии. Тайловая обработка обязательна для больших сцен.

## 8. Этапы

**M0 — Разведка (без кода плагина).** Скачать 1–2 реальных GCOV L-диапазона (PROVISIONAL), изучить структуру, подтвердить пути слоёв, единицы, CRS, статус в метаданных. Зафиксировать результаты в `docs/product_notes.md`. Закрыть все пометки **[ПРОВЕРИТЬ]**, на которые это влияет.

**M1 — Ядро чтения.** Backend'ы A1, A2, авто-выбор, инспектор, загрузка выбранных слоёв в проект с корректным CRS. Юнит-тесты на синтетических файлах.

**M2 — Поиск и загрузка.** Б1, Б2 (или Б3), авторизация EDL через `QgsAuthManager`, footprints, очередь, отмена, статус BETA/PROVISIONAL.

**M3 — Растительность.** Пресеты 1–3, 5 (В1/В2), стили, экспорт GeoTIFF/COG, Processing-алгоритмы.

**M4 — Временные ряды и качество.** Пресет 4, маски, предупреждения о смешивании данных.

**M5 — Расширения.** A3, A4, Б4 (стриминг), поляриметрия (В3), Г3 (CLI).

После каждого этапа: рабочий плагин, который можно установить из ZIP, и короткие заметки о том, что проверено на реальных данных, а что нет.

## 9. Тестирование и приёмка

- Юнит-тесты `nisar_core` без QGIS (pytest). Синтетические HDF5-файлы, имитирующие структуру GCOV (малый размер), в репозитории; реальные продукты в репозиторий **не** коммитить.
- Интеграционные тесты в QGIS 3.28 LTR и в актуальной 4.x: открытие файла, корректный CRS, экспорт GeoTIFF, отмена задачи.
- Проверка обеих веток чтения (GDAL ≥ 3.13 и < 3.13).
- Проверка на файле ≥ 5 ГБ: пик памяти не выше согласованного лимита, GUI отзывчив.
- Тест реестра пресетов: у каждого пресета заполнены все поля, есть RU и EN тексты, `hint` ≤ 100 символов, для каждого есть QML-стиль; пресет с недостающими слоями отображается неактивным с причиной.
- Приёмка v1: пользователь ищет сцену по экстенту, скачивает GCOV, получает слой HV в дБ и RVI с правильной геопривязкой и экспортирует в GeoTIFF — без единой строки кода.

## 11. Правила работы агента

- Начинай с M0. Не пиши код, опирающийся на непроверенные пути слоёв и единицы.
- Работай малыми шагами: один backend/алгоритм — один коммит с тестом.
- Перед добавлением зависимости — спроси, есть ли она в стандартной поставке QGIS; зависимости вне неё делай опциональными с внятным сообщением об установке.
- Все пользовательские сообщения об ошибках — на языке интерфейса, с конкретным советом («обновите QGIS до 4.2» / «включите режим совместимости .nc»).
- Если факт из этого файла противоречит реальному файлу данных или актуальной документации ASF (nisar-docs.asf.alaska.edu), **доверяй данным и документации**, а расхождение фиксируй в `docs/product_notes.md`.
- Не выдумывай названия групп HDF5, параметров API и версий пакетов — проверяй.
